# PLAN — indic-voice-agent-eval

## Working backwards (what the hiring manager sees)
A public repo `Shashank-VK/indic-voice-agent-eval` with a README that reads like an
eval report: a fixed set of Hindi/Hinglish customer-support utterances, a harness
that runs them through a real STT pipeline (faster-whisper tiny, local, free), and
a measured report — WER, p50/p95 latency, cost per 1k calls, failure-mode matrix
(code-mixing, regional accents, background noise). One-command repro (`python run_eval.py`).

building the evals and instrumentation that make quality measurable."

## Metric definitions
- WER = (S+D+I)/N against ground-truth transcripts, computed on normalized text.
- Latency: wall-clock STT time per utterance; p50/p95 across the set.
- Cost per 1k calls: measured per-utterance latency × stated pricing assumption
  (free local compute; report states "local compute assumed $0/hr for measurement;
  cloud-equivalent shown with the provider's published price" — no invented prices).
- Failure-mode matrix: per-tag mean WER + p95 latency, so regressions per failure
  mode are visible.

## Anti-invention rules (hard)
- Every metric measured from a real run of the harness, never estimated or typed in.
- Every repo link live and public.
- No skills claimed the code doesn't show. No secrets in code.
- gTTS needs network; if offline, synthesis falls back to a documented local path —
  the report must say which path produced the numbers.
